# 《企业级 AI 编程实战营》毕业总结

## 我是谁，为什么来

我是一名独立开发者。平时写代码已经在用 AI，但基本是想到哪问到哪，没有成体系的方法。报名是想把 AI 编程学深一点，把相关的知识体系补起来。

开篇里有一句话我比较认同：「工程师在 AI 时代最大的风险，不是不会用工具，而是没有判断。」

## 按「认知、驾驭、进阶」复盘

### 认知

认知篇和扩展篇帮我把一些零散的概念串了起来，比如 AI 编程的本质、SDD 和 Harness、Agent 在技术上是什么、Spec-Kit、Skills、Hermes Agent。

结合课程内容，我写了一篇 OryxOS 和 Hermes Agent 的对比，从功能、技术架构、企业价值三个角度看。写之前我对 Agent 的理解差不多就是「大模型 + 工具调用」；写完后清楚了一点：除了模型和工具，还要考虑循环怎么跑、上下文怎么组装、状态放在哪、权限边界在哪、由谁触发。

### 驾驭

四个项目里我只参与了 OryxOS。7 月底到 10 月中旬，我在上游仓库有 105 个提交，大致分三类：

- 58 个是在 GitHub 上合并 PR 产生的合并提交，其中 3 个是我自己的 PR，其余是其他同学的；
- 26 个是修复（`fix`）；
- 其余是发版、CI、文档相关的提交。

**修复。** 主要集中在 8 月中旬，大部分和沙箱、文件工具的安全边界有关：

- SSRF 防护：拦截 NAT64、IPv4-mapped 地址的绕过写法，HTTP 工具校验 http(s) 协议和 host。
- 文件工具与软连接：删除时不跟随软连接，grep/glob 遍历前先解析真实路径，复制、移动时拒绝目录。
- 通知重定向：每一跳重新校验白名单。
- 其他：控制台和 Shell 输出的字符集解码、RestClient 超时、本地 vLLM/Ollama 端点强制 HTTP/1.1。

这些问题多数是边界情况，比如软连接、重定向、IPv6 的几种嵌入写法。代码看上去没问题，换一种输入就能绕过。这让我对开篇说的「做 OryxOS 时被沙盒安全坑到」有了具体的体会。

**用 SDD 拆任务。** 结业作业里，我复用项目已有的宪法，用 Spec Kit 走了 specify → clarify → plan → tasks，把 OryxOS 的第一个任务「对接 LLM」拆成了 47 个任务。过程中发现四份项目文档有三处说法不一致：

- token 用量是写日志还是落库；
- 验收要跑通一家还是两家模型；
- 用 `ChatClient` 还是 `ChatModel`。

最后都按宪法的优先级定了下来。我的体会是，文档之间会有冲突，需要事先约定以谁为准。

**给 AI 划边界。** 有一次让 AI 发版本，本地测试没过，它自己开了个分支去改代码。代码本身没问题，但不是我要它做的事。之后发版我都会先说清楚：只发版，门禁失败就停下来问我。

### 进阶

这部分主要是参与 OryxOS 的维护：

- **合并 PR**：合并了 58 个 PR，内容包括 SSRF、凭证脱敏、Windows 安装脚本、容器沙箱、人格库、钉钉/飞书通知等。
- **发版**：0.1.2 到 0.1.8 共 7 个版本由我发布，流程是切 release 分支、改版本号、补 CHANGELOG、过 CI、打 tag。中间也出过问题，比如 0.1.3 回滚过一次，0.1.7 的 PR 合并后忘了推 tag，没能及时发布。
- **CI 和小功能**：拆分 OWASP 检查、加 CI 并发控制、加 gitleaks 密钥扫描、接入每周的 Dependabot 依赖更新；另外加了一个功能，让 MCP server 可以单独配置请求超时（#521）。

## 收获

1. **一套能直接用的方法。** 课程里讲的方法比较实用，比如用 SDD 先定原则、再写规格、最后写代码，用宪法和 Skills 固化团队约定。这些我在 OryxOS 里都用过。
2. **认识了一些大佬，参与了开源项目。** 和同学一起写代码、互相 review，比单纯听课收获多。
3. **对 AI 编程有了一个大致的认知框架。** 现在知道一个 Agent 系统由哪些部分组成，也知道怎么用规格去约束 AI 干活。

## 有没有解决工作中的关键问题

暂时没有。还没有因此换到新工作，也没有在具体业务里落地项目。目前的收获主要是建立了 AI 编程的认知框架，之后在独立开发中再慢慢用起来。

## 建议

节奏有点快。不少内容刚跟上就进入下一个主题，消化时间不够。可以适当放慢一些，或者每个项目结束后多留点复盘时间。

## 想说的话

老师很专业，方法很实用；班班很尽责，有问题能及时找到人。也谢谢这段时间一起写代码、一起 review 的同学。
